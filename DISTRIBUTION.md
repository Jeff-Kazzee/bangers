# Distribution and source ownership

## Current source

The canonical public repository is `Jeff-Kazzee/bangers`. This repository owns reusable mechanics, generic research protocols, public creator studies, platform playbooks, and release artifacts.

## Intended portfolio surface

The Little AI Company should offer and link to BANGERS as part of its public tool portfolio. Moving the repository into that GitHub organization, publishing a release, or changing installation instructions is an outbound action and requires Jeff's explicit approval.

## Private overlays

Jeff-specific voice, business context, unpublished proof, audience priorities, and private research stay in HQ under `bangers`, `Brain/Skills/jeff-voice`, and related Brain content files. Public BANGERS may define an extension seam, but it must not absorb private overlays.

## Release flow

1. Update reusable mechanics in the public source.
2. Run the writing checker, JSON validation, link checks, and package review.
3. Review the public diff for private paths, claims, and data.
4. Create a versioned release only after explicit approval.
5. Update portfolio links after the release exists.

Do not maintain separate public copies that can drift. Other organization or profile repositories should link to the canonical source.

## Zo Computer build

`dist/zo/bangers/` is generated by `scripts/build-zo-skill.mjs`, never hand-edited. Zo has no plugin system, so the build folds the twelve plugin procedures into one Agent Skill: a small router in `SKILL.md` plus the procedures as reference files that load on demand. The script strips plugin frontmatter, rewrites `${CLAUDE_PLUGIN_ROOT}` paths and bare procedure mentions to paths relative to the skill root, and copies `references/` and the writing checker.

Editing the generated output directly reintroduces exactly the drift this section forbids. Change the source skill and rerun the build.
